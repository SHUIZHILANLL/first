# 猜数字小游戏（Guess the Number）

一个用 Python 写的命令行小游戏：**电脑随机想一个 1~100 的整数，你来猜，它会告诉你"大了"还是"小了"，猜中后统计你一共猜了几次。**

这是通识任务 2 的第一个练手项目，目标是"单文件 + 逻辑简单看得懂 + 会用命令行跑 + 会用 git 管起来"。

---

## 一、怎么玩

1. 电脑在 1~100 里随机挑一个数，不告诉你。
2. 你输入一个猜测。
3. 电脑告诉你 **大了** 还是 **小了**，你根据提示缩小范围。
4. 猜中后，程序告诉你一共猜了几次，并给一句评价。
5. 可以按 `y` 再来一局，也可以中途输入 `q` 直接退出。

### 玩法示例

```
欢迎来到『猜数字小游戏』！

==========================================
我想好了一个 1~100 的整数，你来猜猜看！
==========================================
请输入你猜的数字（1~100，输入 q 退出）：50
  小了！  （这是你第 1 次猜）
请输入你猜的数字（1~100，输入 q 退出）：75
  大了！  （这是你第 2 次猜）
请输入你猜的数字（1~100，输入 q 退出）：62
  大了！  （这是你第 3 次猜）
请输入你猜的数字（1~100，输入 q 退出）：56
  小了！  （这是你第 4 次猜）
请输入你猜的数字（1~100，输入 q 退出）：59
  恭喜你，猜中啦！答案就是 59。
  你一共猜了 5 次。
  评价：不错，思路很清晰。

再来一局吗？(y = 再来 / 其他键 = 结束)：n
谢谢游玩，再见！
```

> 小技巧：每次都猜当前范围的中间值（二分法），1~100 最多 **7 次**一定能猜中。

## 四、代码逻辑说明

全部代码都在 `guess_number.py` 一个文件里，一共五个部分，从下往上看就是整个流程。

### 1. 准备阶段

```python
import random   # 随机数模块，让电脑"随便想一个数"
import sys      # 系统模块，读命令行参数、设置输出编码
```

`setup_console()` 把输出编码固定成 UTF-8。因为 Windows 的 cmd 默认可能是 GBK 编码，不改的话中文提示可能变乱码甚至直接报错。

### 2. 工具函数 `read_guess(low, high)`

专门负责"把玩家输入变成一个合法整数"，它把脏活累活都挡在这里：

- 输入 `q` → 返回 `None`，表示玩家想退出；
- 输入空回车 → 提示重输，`continue` 回到循环开头；
- 输入 `abc` → `int()` 会抛 `ValueError`，用 `try/except` 接住并提示"这不是一个整数"；
- 输入 `999` → 超出 1~100，提示"超出范围"。

只有全部合法才 `return` 出去。写成独立函数的好处是：主流程不用到处写判断，一眼就能看懂。

### 3. 核心函数 `play_one_round()`

一局的全部逻辑：

```python
answer = random.randint(low, high)   # 电脑出题
count = 0                            # 计数器
```

然后是一个 `while True` 死循环，每轮做三件事：

1. 拿玩家的猜测（调用 `read_guess`）；
2. 计数器 `count += 1`；
3. 用 `if / elif / else` 三种情况比较：
   - 猜的比答案大 → 打印"大了"；
   - 猜的比答案小 → 打印"小了"；
   - 相等 → 打印"猜中"和总次数，然后 `return count` 结束这一局。

`return` 一执行，循环和函数同时结束——这就是"猜中才退出"的实现方式。

### 4. 评价函数 `judge(count)`

纯粹好玩的加分项。因为二分法最多 7 次能猜中 1~100，所以用 7 当分界线给出不同评语。

### 5. 主函数 `main()`

打印欢迎语 → `while True` 里调用 `play_one_round()` 玩一局 → 问"再来一局吗" → 输入不是 `y` 就 `break` 结束。

文件最后这行是 Python 的固定写法：

```python
if __name__ == "__main__":
    ...
```

意思是：**只有直接运行这个文件时才执行下面的代码**。如果别的程序 `import guess_number`，就不会莫名其妙自动开局。`--test` 参数也是在这里分流的。

## 五、关于 Markdown 和 README（自学笔记）

### Markdown 是什么

Markdown（简称 md）是一种**纯文本的轻量标记语言**，用几个简单符号就能排出标题、列表、表格、代码块，写起来不用碰鼠标点格式。它本质还是纯文本，所以任何编辑器都能打开，也特别适合配合 Git 做版本管理（能清楚看出改了哪一行）。

### README 是干什么的

`README` 就是"读我"，是别人（也包括几个月后的自己）打开一个项目时**第一眼看到的东西**。它回答几个问题：

- 这是个什么东西？
- 我怎么把它跑起来？
- 它怎么用？
- 有哪些注意事项？

GitHub 会自动把仓库根目录的 `README.md` 渲染在项目首页，所以它相当于项目的门面。名字用 `README.md` 算约定俗成，写成 `readme.md` 也照样能用（GitHub 不区分大小写）。

### 常用语法速查

| 想写的东西 | 写法 | 说明 |
| --- | --- | --- |
| 一级标题 | `# 标题` | 井号数量对应标题级别，最多 6 级 |
| 二级标题 | `## 标题` | 井号后建议留一个空格 |
| 加粗 | `**加粗**` | 也常用 `__加粗__` |
| 斜体 | `*斜体*` | 也常用 `_斜体_` |
| 无序列表 | `- 内容` | 也可以用 `*` 或 `+` |
| 有序列表 | `1. 内容` | 序号会自动排 |
| 链接 | `[文字](网址)` | 方括号放显示文字，圆括号放地址 |
| 图片 | `![说明](图片路径)` | 比链接多一个感叹号 |
| 行内代码 | `` `代码` `` | 用反引号包起来 |
| 代码块 | 三个反引号 + 语言名 | 见本文件里的示例 |
| 引用 | `> 文字` | 用来强调一段话 |
| 分割线 | `---` | 单独一行三个减号 |
| 表格 | `| A | B |` | 第二行用 `| --- | --- |` 定表头 |
| 复选框 | `- [x] 已完成` | `[ ]` 是未完成 |

### 写 README 的一点心得

1. **开头一句话说清楚这是什么**，别让人猜。
2. **运行步骤要能照抄**：写清在哪个目录、敲什么命令，最好给完整命令而不是"自行配置"。
3. **给个示例输出**，比一大段文字描述直观。
4. **代码块标注语言**（如 ` ```python `），GitHub 会做语法高亮。
5. 保持更新：功能变了，README 跟着变，否则它比没有还坑人。
